# Booking & Promotion Submission System

This document outlines the architecture for the two direct-to-Strapi submission endpoints used in the Dental Application frontend.

## Architecture Change

Previously, the Next.js frontend used a proxy API route (`/api/contact`) to communicate with Strapi. This was responsible for sending email notifications to staff members and validating Google reCAPTCHA tokens.

To improve real-time performance and decouple the frontend further from Next.js serverless functions, the submission models were migrated to submit data **directly from the browser to the Strapi CMS API**. 

### 1. Booking Submissions
- **Frontend Component**: `src/components/booking-modal/BookingModal.tsx`
- **Strapi Content Type**: `booking-submission`
- **Payload Schema**:
  - `full_name` (String, required)
  - `phone_number` (String, required)
  - `service` (String, required)
  - `other_service` (String)
  - `message` (Text)
  - `booking_status` (Enumeration: "new", "contacted", "scheduled", "completed", "cancelled")
- **Workflow**:
  1. User fills out the Booking form in the frontend.
  2. The form validates the inputs.
  3. `fetch` is called against `${NEXT_PUBLIC_STRAPI_URL}/api/booking-submissions` using the `NEXT_PUBLIC_STRAPI_API_TOKEN`.
  4. Strapi validates the payload and creates a new entry in PostgreSQL (`booking_submissions` table).
  5. The UI shows a success message.

### 2. Promotion Submissions
- **Frontend Component**: `src/components/blocks/PromotionModal.tsx`
- **Strapi Content Type**: `promotion-submission`
- **Payload Schema**:
  - `phone_number` (String, required, min 7 chars)
  - `status` (Enumeration: "new", "contacted", "completed", "cancelled")
  - `ip_address` (String)
  - `user_agent` (Text)
- **Workflow**:
  1. User views the Promotion modal and enters their phone number to claim an offer.
  2. The form validates the phone number.
  3. `fetch` is called against `${NEXT_PUBLIC_STRAPI_URL}/api/promotion-submissions`.
  4. Strapi creates a new entry in PostgreSQL (`promotion_submissions` table).
  5. The UI shows the success checkmark view.

## Security & Notifications Trade-offs

By bypassing the `/api/contact` route, please be aware of the following architectural implications:
1. **Google reCAPTCHA Bypass**: The frontend executes `react-google-recaptcha-v3`, but because the request goes directly to Strapi, Strapi does *not* natively verify this token against the Google reCAPTCHA secret key. 
2. **Staff Email Notifications**: The previous Node.js `nodemailer` logic lived inside Next.js. Because the browser calls Strapi directly, Node.js never executes the `sendBookingNotifications` script.
   * **Recommendation**: If staff emails are required, configure a Strapi Webhook or Strapi Lifecycle hook (`afterCreate`) to dispatch the email.

## Data Storage
Both endpoints save data directly to the Strapi PostgreSQL database (`100.68.50.41`). The tables are automatically generated by Strapi based on the `schema.json` configurations in `strapi-cms/src/api/`.
